# vibecoding-retro

**给高频使用 AI 的产品经理的工作流复盘工具。** 每段 vibecoding 对话结束后说一句"复盘",得到一份带证据的诊断报告;报告存进本地档案;每周做一次跨项目的交叉汇总。

形态是一个 **Claude Code skill**——**界面就是对话**。没有网站、没有服务器、没有数据库,数据是你本地的几个纯文本文件,可 git、可手改、可删。

## 它和别的工具有什么不同

ccusage、token-dashboard 这类工具回答"我花了多少 token";claude-retrospective 这类回答"我的项目和配置有什么问题"。**没有工具回答"这次会话说明我这个人缺什么"**——这是本产品的位置。

效率数字只是证据基底,**诊断才是正文**。

## 核心闭环

```
发现问题 → 从知识库给出带出处的做法 → 记录待实践 → 下次复盘验证有没有用
```

北极星指标是**建议实践率**(已实践 / 非放弃的建议),目标 ≥50%。低于这个值,说明建议不够可执行或不够对症——反省的是建议质量,不是你的执行力。

## 主要功能

### 1. 数据采集(全自动)

流式解析 `~/.claude/projects/*/*.jsonl`,一次拿到:

| 类别 | 内容 |
|---|---|
| 基础 | token 四项、模型分布、轮次、活跃时长、实际推理档位、skill 归因 |
| **诊断证据** | 用户消息全文(过滤掉工具结果、命令、子代理、上下文压缩摘要) |
| **逐轮账单** | 每个 prompt 花了几次请求、调了什么工具、烧了多少 token、上下文涨了多少 |
| 浪费模式 | 重复读同一文件、超大工具结果、上下文拖拽成本、缓存命中率、膨胀趋势、压缩次数 |
| 安全 | **密钥泄漏扫描 + 自动脱敏**——11 类前缀 + 高熵串启发式,覆盖你的消息与助手 thinking |
| 校正项 | 模型安全回退标注(避免按非你选择的模型评档位) |
| 自检 | **schema 健康度**——日志格式变了会报警,而不是静默出错 |

四个容易被忽略但很关键的处理:

- **上下文压缩摘要不算真人轮次**。它是系统生成的,既污染轮次统计,更会作为"你的原话"喂进诊断
- **活跃时长 ≠ 会话跨度**。跨天会话的跨度可达几千分钟,绝大部分是挂机。评分用 `active_min`
- **助手的 thinking 正文明文写在本地日志里**。你贴过的密钥如果被复述,同样落盘了,所以扫描覆盖它
- **解析输出里的密钥被替换成 `«已隐去:类型,长度»`**。解析结果会进报告、进档案、可能被转发,任何一环都不该再出现密钥字符

### 数字带可信度,不许含糊

每个指标标 `exact` / `derived` / `estimated`:

- `exact` — 来自 API usage 或直接计数(token、轮次、请求数),可当事实陈述
- `derived` — 由精确值按明确规则推算(活跃时长、缓存命中率、上下文增长),要说明口径
- `estimated` — 含拍脑袋的换算(工具结果大小按 `len/4` 粗估,中文误差可达数倍),**报告里必须带"约",且不能独自支撑一条诊断**

**任何情况下不把 token 换算成美元**——订阅制下那是估算的估算,还要维护一张会过期的定价表。只说 token 和倍数。

### schema 自检:这个产品的保险单

本产品读的是 Claude Code **未公开承诺的内部日志格式**。官方改字段不会通知,解析器会静默失真——**错的数字比没有数字更危险**。所以每次解析都自检:版本没见过、`promptId` 缺失、`usage` 缺失,都会进 `degraded` 并要求报告如实说明。

配套地,月度知识库更新协议里加了三类必过信号:日志 schema 变化、官方内置能力、同类工具动向。发现 schema 变更是最高优先级。

### 2. 五维效率评分

token 效率、模型/模式选择、时长与迭代、提示词质量、**委托校准**,各 1–5 分。

委托校准是本产品独有的指标:**判断类决策(做什么、为谁做、先做哪个)该留在人这边,执行类工作(样板代码、格式、机械重构)该充分交给 AI**。人机边界感正在变成 AI 时代 PM 的第一能力,而 vibecoding 会话恰好是它的最佳观测场。

冷启动用启发式基准;档案攒够 10 条同复杂度记录后,自动切换成你的个人中位数基线。

**"超出应有值"的分母只能是你自己。** 通用的"应有值"不存在——L 级任务花 S 级十倍 token 是正常的。所以偏差只跟你同复杂度档位的历史中位数比,不足 10 条就不出数(没有分母就没有超标)。

而且**偏差只负责开启调查,不负责下结论**:某个指标飘了 2.3 倍,接下来必须回到逐轮账单找出是哪一轮、什么行为造成的。找不到行为原因就不写进诊断。

### 3. 能力缺口诊断(核心)

**思维架构类**:T1 问题定义 / T2 验收标准 / T3 范围控制 / T4 假设外显化 / T5 抽象层级切换 / T6 委托校准
**技术类**:J1 概念词汇缺口 / J2 方案评估 / J3 验证行为 / J4 知识沉淀

四条铁律,防止复盘变成挨骂:

- 每条诊断**必须引用本次会话的具体证据**(第几轮、哪句话),没有证据不输出
- 措辞是**假设**不是断言,由你确认或否决
- **每次最多 2 条**——诊断过载 = 复盘疲劳 = 产品死亡
- 弱证据只默默记台账,不打扰你

### 4. 缺口台账:看见成长

诊断进台账累积,状态自动转移:

```
watching ──确认 3 次──→ structural(升级为结构性缺口,给学习建议)
   │                          │
   │                          └──连续 5 次会话未出现──→ graduated 🎓
   └──被否决 2 次──→ suppressed(停检,防止误判模式反复骚扰你)
```

**看见成长和看见缺口同等重要**——毕业机制就是为此存在的。

### 5. 知识库与学习闭环

内置 29 条精选技巧,按诊断类别索引,来源三级分级(`official` > `verified` > `blogger`),每条含生效验证方式。

**建议必须个性化**:直接搬知识库原文等于没给建议。每条要绑定你的具体资产(哪个文件、哪个习惯)、写成今天能做完的最小改动、自带验证方式,记进待实践清单的 `note`,下次按 note 核对而不是按条目泛泛问。

**建议要配一个数,而且是真数。** 两条腿:

- **当场:反事实圈定。** 从逐轮账单里把**已经发生、且已被作废**的消耗圈出来——"第 7 轮到第 9 轮的 48K,在你第 9 轮改口后全部作废"。这是把实测数字做减法,**不是模拟**;"预计能省 $0.4"那种编出来的预测是禁止的
- **下次:采纳前后实测。** `ledger.py effect --tip KB-24` 比较采纳日期前后同档位会话的实测中位数。两侧都是真实数据,可以直接陈述;但每侧不足 3 条时只能说"前后有变化",不能说"是这条建议带来的"

找不到明确的转向点就不给数。**宁可不给,不要给假的。**

### 6. 报告归档与周报交叉汇总

每次复盘的**报告全文**存进 `reports/`,这是周报唯一的素材来源。周报回答单次复盘答不了的问题:

- 这周精力实际落在哪个项目,和你自己说的优先级一致吗
- 同一个坑在几个项目里重现(这是 J4 的硬证据)
- 台账动态、实践率、待实践清单核对

**周报只给下周一件事**——给清单会和单次复盘的建议叠加,直接压垮注意力预算。

### 7. 复盘覆盖率:忘了复盘的会话会现形

装了 plugin 会带一个 SessionEnd 钩子,它**只往索引里追加一行**(会话 id、项目、时间),不生成报告、不弹通知、不调模型。周报据此报出"本周 7 段会话,复盘了 2 段"。

为什么钩子只做这么少:**"对话结束"在 Claude Code 里不是个干净的概念**——一个 session 可以跨天、可以 resume,SessionEnd 触发一次不代表你说完了。所以复盘仍由你主动发起,这是设计不是限制。钩子补的只是唯一那个真实漏洞:忘了复盘的会话原本是隐形的。

而且周报**只陈述不催促**——你有权只复盘你在意的那几段。

## 安装

本仓库是一个 **Claude Code plugin**。在 Claude Code 里执行:

```
/plugin marketplace add <你的仓库地址>
```

```
/plugin install vibecoding-retro@vibecoding-retro
```

要求:Claude Code + Python 3.9+。**零 pip 依赖**,只用标准库,装了 Claude Code 的机器直接能跑。

装完带三样东西:复盘 skill、`/retro` 与 `/weekly-retro` 两个命令、一个只登记会话索引的 SessionEnd 钩子。

也可以只装 skill(不要命令和钩子):

```bash
git clone <仓库地址> /tmp/vr && cp -r /tmp/vr/skills/vibecoding-retro ~/.claude/skills/
```

验证安装:

```bash
python3 ~/.claude/skills/vibecoding-retro/scripts/parse_session.py --list --limit 3
```

## 使用方法

日常只需要三句话,其余都是脚本自动做的:

| 你说 | 发生什么 |
|---|---|
| **复盘** 或 `/retro` | 解析本段对话 → 五维评分 → 缺口诊断 → 带出处的建议 → 报告归档 |
| **周复盘** 或 `/weekly-retro` | 读本周全部报告 → 跨项目交叉汇总 → 下周一件事 |
| **更新知识库** | 按月度协议过一遍信号源,产出 diff 给你审核后才写入 |

复盘结束时会问你两个问题:**"诊断你认吗?"**(决定台账计数)和 **"哪些建议列入待实践?"**(决定下次验证什么)。这两个回答是闭环的关键,不是客套。

### 首次使用

档案为空时,前两段(上次实践验证、成长轨迹)会是空的。所以第一次复盘会主动问你要不要**回溯扫描最近 30 天**——跨会话才看得见重复踩坑和成长趋势,单看一次会薄很多。

### 其他环境

Cursor / Claude.ai 没有本地日志,走问卷路径(≤6 问,首条 prompt 原文必收)。证据不足的诊断项不输出——**贴多少诊断多少**。

## 数据在哪

全部在 `~/.claude/vibecoding-retro/`:

| 文件 | 内容 |
|---|---|
| `sessions.jsonl` | 每段复盘的指标、评分、诊断、建议(append-only) |
| `gap-ledger.json` | 缺口台账、待实践清单、词汇台账 |
| `reports/` | 每次复盘的报告全文 + 周报 |
| `session-index.jsonl` | SessionEnd 钩子登记的会话索引(只有 id/项目/时间) |
| `learnings.md` | 你对建议的反馈记录 |

**全部在你自己的机器上,没有服务器,不发一个网络请求。** 想删就删,想改就手改,可以 git。

**绝不写入**:代码内容、密钥、敏感路径。档案只存指标、缺口计数、条目 ID 和一句话摘要。密钥扫描的输出只报"第几轮、什么来源、什么类型、多长",**不回显任何密钥字符**;解析结果里命中的密钥被替换成 `«已隐去:…»`。

## 直接调脚本(可选)

平时不需要,skill 会自己调。

```bash
# 解析
parse_session.py --latest                       # 最近的会话
parse_session.py --file <日志> --since <时间戳>  # 只看某段增量
parse_session.py --list --days 7                # 列出最近 7 天的会话

# 台账
ledger.py status                       # 缺口全貌,并执行状态转移
ledger.py tips --pending               # 待实践清单
ledger.py practice-rate                # 北极星指标
ledger.py weekly-pack --days 7         # 周报素材
ledger.py baseline --complexity M      # 个人基线(需 ≥10 条同档记录)
ledger.py compare --session-json <f> --complexity M   # 本次 vs 基线,超出几倍
ledger.py effect --tip KB-24           # 某条建议采纳前后的实测对比

# 趋势
trend_report.py --last 10
```

## 调阈值

判断标准全部集中在两个文件里,直接改数字即可,不用碰代码:

- `references/capability-diagnosis.md` —— 诊断信号、台账升级/毕业阈值
- `references/scoring-rubric.md` —— 复杂度档位、各维度评分线

脚本侧的浪费阈值在 `scripts/parse_session.py` 顶部(重复读取次数、超大结果 token 数、挂机判定间隔)。

## 边界

- **自动采集只支持 Claude Code**,因为它需要本地会话日志
- **密钥扫描不覆盖工具结果**(你的消息和助手 thinking/正文都覆盖)
- **诊断的是行为模式,不是人格**;禁止心理分析式措辞
- 知识库的写入(收录/修订/弃用)**一律先给 diff、经你确认**
- **依赖未公开承诺的日志格式**——这是本产品的架构赌注。缓解手段是 schema 自检 + 月度信号源巡检,但 Claude Code 大改日志格式时仍可能需要跟进修复
