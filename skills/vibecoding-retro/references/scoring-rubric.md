# 评分规则(四维度,各 1–5 分)

先给任务定复杂度档位,再逐维度打分。有历史基线(≥10 条同档记录)时用"相对基线"列,否则用"启发式基准"列。

## 任务复杂度档位

- **S(简单)**:改配置、修 typo、写单个函数、回答代码问题。预期 ≤10 轮、单文件改动
- **M(中等)**:实现一个完整功能、跨 2–5 个文件的重构、调试一个 bug。预期 10–30 轮
- **L(复杂)**:新模块/新服务、架构调整、涉及 5+ 文件或需要设计决策。预期 30 轮以上,应先 plan

档位由任务描述 + 实际改动范围综合判断,记入档案的 `complexity` 字段。

## 维度一:Token 效率

检测以下浪费模式(思路借鉴 token-dashboard 的规则引擎),每命中一项扣分:

| 浪费模式 | 检测方法 | 扣分 |
|---|---|---|
| 重复读取同一文件 ≥3 次 | 统计 Read 工具对相同路径的调用 | -1 |
| 单次工具结果超大(>30k tokens 估算) | 工具结果字符数 / 4 粗估 | -1 |
| 缓存命中率低:cache_read / (input + cache_read) < 50%,且会话超过 10 轮 | usage 字段计算 | -1 |
| 返工消耗:因方向错误推倒重来的轮次占比 >25% | 浏览用户消息识别"不对,重来"类信号 | -1 |
| 上下文膨胀后未清理:会话后半程 input_tokens 持续 >150k 且任务本可拆分 | 逐消息 usage 趋势 | -0.5 |

- 起评 5 分,按上表扣,下限 1 分
- **相对基线**:token总量/轮次 比同档位基线低 20% 以上 → 在扣分结果上 +0.5(封顶 5);高 40% 以上 → 额外 -0.5
- 无 token 数据时:仅凭返工比例给一个粗略分并标注"低置信",或直接 N/A

## 维度二:模型/模式选择

两个子项各占一半:

**模型档位匹配**(以 Anthropic 系为例,其他家按同级类比):

- S 档任务用旗舰模型(Opus/Fable 级)→ 过度配置,3 分;用中档(Sonnet 级)或以下 → 5 分
- M 档任务用中档 → 5 分;用旗舰 → 4 分(可接受);用轻量档(Haiku 级)且出现多次纠偏 → 2 分
- L 档任务用旗舰 → 5 分;用中档且顺利 → 5 分;用中档且反复返工 → 3 分(该升不升)
- 会话中途因卡住而升档、升档后立刻解决 → 说明起点选低了,按起点模型评但注明"及时止损 +0.5"

**工作流模式匹配**:

- L 档任务直接开写、没有 plan/设计环节,且出现方向性返工 → 2 分
- L 档任务先 plan(plan mode、先讨论方案、或先写设计文档)→ 5 分
- S 档任务走了冗长 plan → 4 分(轻微浪费)
- S/M 档直接写且顺利 → 5 分

两子项平均为本维度得分。问卷路径下模式信息靠用户口述。

## 维度三:时长与迭代

| 指标 | 启发式基准(S / M / L) | 评分 |
|---|---|---|
| 用户轮次 | ≤10 / ≤30 / ≤60 | 在基准内 5 分;超 50% → 4;超 100% → 3;超 200% → 2 |
| 单一卡点耗时占比 | — | 某个问题占掉 >40% 轮次且最终靠换思路解决 → 额外 -1(说明应更早换思路) |
| 时长 | 与轮次交叉验证 | 轮次少但时长极长(等待、人工介入多)→ 注明但不扣分 |

- **相对基线**:轮次比同档基线少 20% → +0.5;多 50% → -0.5
- 取上述结果的综合,下限 1 分

## 维度四:提示词质量

**首条 prompt 完整度**(满分要素,S 档任务只要求前两项):

1. 目标明确(要做成什么样,有验收标准)
2. 范围/约束(改哪些文件、不能动什么、技术栈)
3. 上下文(相关背景、之前试过什么)
4. 期望的工作方式(先 plan 还是直接写、要不要测试)

**纠偏次数**:浏览用户后续消息,统计属于"补充本可在首条给出的信息"的纠偏(方向性纠正、补约束、纠正误解)。纯粹的迭代反馈(看到结果后自然产生的新想法)不算纠偏。

| 首条完整度 | 纠偏 0–1 次 | 纠偏 2–3 次 | 纠偏 ≥4 次 |
|---|---|---|---|
| 4 要素齐全 | 5 | 4 | 3 |
| 缺 1–2 项 | 4 | 3 | 2 |
| 一句话模糊需求 | 3 | 2 | 1 |

例外:探索性任务("帮我看看这个库怎么用")首条模糊是合理的,按 4 分起评,只看纠偏。

## 建议生成规则

按命中的扣分项映射建议类别:

- 重复读文件 / 上下文膨胀 → `context-hygiene`:建议具体文件加进 CLAUDE.md 的"已知结构"说明,或用 /compact、拆会话
- 首条不完整 + 多次纠偏 → `prompt-upfront-detail`:**直接给出改写后的首条 prompt 示例**,把本次后来补的信息前置
- 档位不匹配 → `model-downgrade` / `model-upgrade`,写明具体模型名
- L 档没 plan → `use-plan-mode`
- 同类问题反复出现(对照历史档案)→ `claude-md-rule`:给出可直接粘贴的规则文本
- 单会话跨多个不相关任务 → `split-task`

优先级 = 预期 token/时间节省 × 实施容易度。最多 3 条,学习档案中被连续拒绝 ≥2 次的类别跳过。
