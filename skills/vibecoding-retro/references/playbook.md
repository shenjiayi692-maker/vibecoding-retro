# 改法手册

按**问题现象**查,每条给一个能今天做完的动作和一个验证方式。

引用时用锚点名(如 `#验收标准写进首条`),**不要在报告里写锚点**——报告里直接说做法本身。

## 提问方式

### #前置目标而非方案
首条先写"我要解决什么问题、谁会用",再写(或干脆不写)技术方案,让 AI 有机会挑战你的方案预设。模型知道"为什么"的时候,方向性错误明显减少。
来源:Anthropic 提示工程文档 https://docs.claude.com/en/docs/build-with-claude/prompt-engineering/overview
验证:下次不再出现"我其实想要的是…"这类推翻。

### #具体指令
指令越具体,一次做对的概率越高。差:"给 foo.py 加测试";好:"给 foo.py 写测试,覆盖用户未登录的情况,不要用 mock,参照 tests/ 里现有风格"。
来源:Anthropic 官方最佳实践 https://www.anthropic.com/engineering/claude-code-best-practices
验证:补充说明和纠正的轮次减少。

### #验收标准写进首条
首条末尾加一段"做完什么样算对:1) … 2) …"。也可以直接给测试用例或预期输出样例。
来源:Anthropic 官方最佳实践 https://www.anthropic.com/engineering/claude-code-best-practices
验证:不再出现"看到结果才发现还需要 X"的大改。

### #前提自查清单
发 prompt 前花 10 秒过一遍:给谁用?跑在什么平台?数据格式和规模?输出中文还是英文?有没有已存在的约定?性能和预算上限?
所有"哦对了忘了说"都对应这张清单上的某一项。可以直接贴在常用位置。
来源:由常见遗漏归纳的社区 checklist 实践
验证:补前提类的纠正降到 0–1 次。

### #让AI先复述
复杂任务发出后加一句"动手前,用三句话复述你的理解和打算的做法"。前提错位在复述里立刻暴露,成本一轮,可能省下十轮。
来源:Anthropic 提示工程文档 https://docs.claude.com/en/docs/build-with-claude/prompt-engineering/overview
验证:方向性返工在头两轮内被拦住。

### #给视觉目标
UI 类任务把设计稿截图、参考网站或手绘线框贴给模型当验收基准,对着目标改而不是凭感觉改。
来源:Anthropic 官方最佳实践 https://www.anthropic.com/engineering/claude-code-best-practices
验证:UI 类任务轮次下降。

## 范围控制

### #本次不做清单
首条加一行"本次不做:X、Y、Z"。负面清单对模型的约束力常常强于正面描述(模型倾向热心加料),对自己也是一份 scope 承诺。
来源:建造者社区共识实践
验证:"顺便再加个"这类话减少,成品和最初描述的偏差缩小。

### #新想法进停车场
会话中冒出的新需求不当场做,回一句"记到 backlog,本次不做"。可以在项目里维持一个 IDEAS.md,让 AI 帮你归档。
来源:多个 agentic coding 工作流分享中的通行实践
验证:单次会话的目标数回到 1–2 个。

### #任务块做完就换会话
换任务就换会话,不要在一个会话里连着做不相关的事。关键是**别把判断交给临场感觉**——定一个你自己看得见的客观触发点(比如"一个任务块做完就换"),而不是"觉得上下文用不上了再换"。
来源:Anthropic 官方最佳实践关于 /clear 的建议,加上"触发点要客观"这一条实践修正
验证:上下文压缩次数降到 0;单次会话的目标数 ≤2。

## 上下文卫生

### #主动clear和compact
任务切换用 `/clear` 清空,长任务中途用 `/compact` 压缩。无关上下文会稀释注意力、推高成本,还会放大重复读文件的浪费。
来源:Anthropic 官方最佳实践 https://www.anthropic.com/engineering/claude-code-best-practices
验证:每轮的 input token 不再单调爬升;缓存命中率回升。

### #子代理隔离脏活
大范围探索(读几十个文件找某段逻辑)交给子代理,主线只收结论。探索产生的海量中间内容不该污染主上下文。
来源:Anthropic 上下文工程文章 https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
验证:超大工具结果减少;主会话每轮 token 下降。

### #结构说明进CLAUDE.md
同一个文件被反复读,说明项目结构信息没沉淀。把关键文件的职责地图写进 CLAUDE.md("支付逻辑在 src/pay/,入口是 handler.ts"),模型就不用每次重新翻。
来源:Anthropic 官方最佳实践与 memory 文档 https://docs.claude.com/en/docs/claude-code/memory
验证:重复读文件的标记消失。

## 方案与模型

### #先出方案再写代码
大任务先让 AI 读代码出方案(plan mode,或明确说"先别写代码,给我方案"),人审完再执行。方案层面的错误纠正是一句话,代码层面是一次返工。
来源:Anthropic 官方最佳实践 https://www.anthropic.com/engineering/claude-code-best-practices
验证:架构级返工消失。

### #用think要深度
在 prompt 里用 think / think hard / ultrathink 分档要求思考深度,难题给足预算。简单任务别用,白花 token。
来源:Anthropic 官方最佳实践 https://www.anthropic.com/engineering/claude-code-best-practices
验证:动手前就排除了坏路径,死磕段减少。

### #模型选择的经济学
探索、问答、机械改动用中低档;方案设计、跨文件重构、疑难 debug 用高档。判断依据是**错误的代价**——错了要大返工的环节值得用贵模型,错了改一句的不值得。
来源:综合各家模型选择文档与社区实践
验证:不再出现"用轻量档反复纠偏"或"用旗舰改 typo"。

## 人机分工

### #决策权两分法
判断类(做什么、为谁做、先做哪个、接受什么代价)自己拿主意,AI 只提供选项和依据;执行类(样板代码、格式、机械重构)充分放权,只验收不插手。
检验句式:向 AI 要"选项 + 各自代价",而不是"你决定"。
来源:Anthropic building effective agents 中人机分工原则的延伸 https://www.anthropic.com/engineering/building-effective-agents
验证:取舍类问题不再出现"你决定吧"。

### #要选项不要答案
产品或技术取舍时用固定句式:"给我 2–3 个方案,各自的代价、规模大十倍后的表现、最简版本分别是什么"。保留你的决策权,同时把 AI 用在它擅长的穷举和分析上。
来源:建造者社区中 PM 类使用者反复提及的模式
验证:不再零质疑接受第一个方案。

### #机械活整批外包
发现自己在手动做重复操作(逐个改导入、手查语法、格式校对)立刻停下,把规则描述清楚交给 AI 批量执行。
来源:Anthropic 官方最佳实践 https://www.anthropic.com/engineering/claude-code-best-practices
验证:"我自己手动改了"这类话消失。

## 验证习惯

### #每步验收30秒
每个改动后花 30 秒:看 diff 摘要、跑一下、确认再继续。小步快验,不要攒一堆一起看。bug 越晚发现定位成本越高,在 AI 生成的代码上尤其如此——你没有逐行写过的记忆。
来源:社区共识实践
验证:不再出现"之前哪一步改错了"式的回溯排查。

### #让AI自证
要求 AI 每次改动后自己跑测试/lint 并汇报结果,可以写进 CLAUDE.md 固化("每次修改后运行 npm test 并报告")。验证成本趋近于零,习惯才建立得起来。
来源:Anthropic 官方最佳实践 https://www.anthropic.com/engineering/claude-code-best-practices
验证:不依赖你的自觉,验证也在发生。

### #三个万能追问
接受任何技术方案前问三句:trade-off 是什么?数据或流量大十倍会怎样?最简方案是什么?
你不需要有能力提出替代方案,只需要有能力触发比较。
来源:工程社区通行的方案评审框架
验证:架构级返工被前置成方案阶段的讨论。

## 卡住的时候

### #卡三轮就升维
同一个问题连续 3 轮修不好,强制说一句:"停一下,退回方案层——原来的做法还成立吗?有没有别的路?"把"上升一层"从本能变成规则,规则可以写进 CLAUDE.md 让 AI 主动提醒你。
来源:工程 debug 通行启发式
验证:同层穷举超过 15 轮的死磕段不再出现。

### #先怀疑环境
反复失败而改动"理应有效"时,优先怀疑环境和前提(版本、缓存、配置、数据),别继续改代码。可以让 AI 列出"如果代码没错,还有什么会导致这个现象"。
来源:工程社区通行 debug 启发式
验证:死磕段消失。

### #缺词就地补课
发现自己在绕圈描述某个概念,当场问一句"这个东西的标准术语叫什么?顺便一句话解释它和相邻概念的区别"。30 秒补一个词,长期消除一类模糊表达。
来源:通用学习实践
验证:同一领域不再重复出现绕圈描述。

## 沉淀

### #CLAUDE.md是活文档
每次踩坑后立刻问:这个教训能不能写成一条 CLAUDE.md 规则?它是所有会话的共享前置知识,一次沉淀全部受益。
**写规则时注意触发点**:写成"提醒我 X"就是把判断权交回给了模型,容易落空;写成"做完 X 就做 Y"这种客观触发的形式才可靠。
来源:Anthropic 官方最佳实践与 memory 文档 https://docs.claude.com/en/docs/claude-code/memory
验证:同一个坑不再跨会话重现。

### #重复流程变命令
同一套操作流程第三次出现时,固化成 slash command 或 skill。判断标准很简单:你已经能把流程口述清楚 = 它可以被固化。
来源:Anthropic 官方最佳实践 https://www.anthropic.com/engineering/claude-code-best-practices
验证:该流程的会话轮次骤降。

### #会话末尾一分钟沉淀
每次结束前让 AI 回答:"本次有什么值得写进 CLAUDE.md 或笔记的?"由 AI 提炼,你只做取舍。
来源:社区通行实践
验证:下次同类问题不再从零讲起。

## 加新条目

只在两种情况下加:①这次遇到的问题手册里没有对应改法 ②现有改法被验证无效需要替换。

加之前过三关:**可操作**(是一个动作,不是一句道理)、**有机制解释**(为什么有用)、**能验证**(下次看什么)。加完给用户看 diff,确认后再写入。

不收:玄学咒语、无法验证的提效宣称、和官方文档冲突且没有说明的做法。
