# 周报模板

周报回答**单次复盘答不了的问题**:这周精力实际花在哪、同一个问题在几个项目里重现、有没有在变好。

**写之前必须逐个读完 `reports_to_read` 里的报告全文。** 只看数字写出来的周报和单次报告没有区别——那是这个功能唯一的失败方式。

---

## 格式

```markdown
# 本周复盘(<起> ~ <止>)

<一句话:这周主要在干什么,状态如何。>

## 精力去哪了

<按项目列:几段会话、多少活跃时间、大致在做什么。>
<如果和用户自己说的优先级不一致,直接指出来——这是周报最有价值的观察之一。>

## 反复出现的问题

<只写在 ≥2 段会话里出现过的。每条注明出现了几次、分别在哪几个项目。>
<单次出现的问题不写进周报,它属于当次报告。>

## 下周就改这一件事

<只给一件。>
<为什么是它:出现最多 / 代价最大 / 最好改。>
<具体怎么做,以及下周看什么数据判断有没有用。>

## 素材说明

<只在素材不全时写:>
<- 有 N 段会话没有报告全文,这几段只有数字>
<- 本周有 N 段会话没有复盘(如果 coverage.available)>
```

---

## 三条规矩

1. **最多 2 个问题**,而且优先选跨会话反复出现的。单次的问题属于单次报告
2. **下周只给一件事。** 给清单会和单次复盘的建议叠加,直接压垮注意力
3. **`reports_missing` 和 `coverage.not_retroed` 如实说**,不要假装素材完整

## 关于覆盖率

`coverage` 显示这周有多少段会话没复盘。**只陈述,不催促**——用户有权只复盘他在意的那几段,反复催会把这个功能变成负担。

`coverage.available` 是 false(钩子没装)就整段不提,不要解释钩子是什么。

## 同样的规矩

报告里不许出现字母编号、档位缩写、分类学名词。不换算美元。估算值带"约"。
